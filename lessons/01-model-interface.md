# 第一课：消息与模型接口

全程使用 VS Code 逐行练习时，先打开 [第一课 A：VS Code 手写步骤](01-vscode-hands-on.md)。本页保留完整课程目标和函数契约。

## 本课只学什么

理解程序怎样把用户输入组织成消息，再调用一次模型接口并取得回复。

先使用离线 Mock 模型，它只返回预先指定的文本。这样可以观察数据流，不受账户、网络和模型随机性影响。真实模型适配在第二课实现。

## 四个概念

| 概念 | 本课中的含义 |
| --- | --- |
| 用户输入 | 终端里输入的一段字符串 |
| `messages` | 按顺序排列的消息列表，每条包含角色与内容 |
| `model.complete(messages)` | 本课约定的模型调用入口，不是特定供应商 SDK 的 API |
| 模型回复 | `complete` 返回的字符串，本课要求原样交回调用者 |

```text
用户输入字符串
  → build_messages：组装系统和用户消息
  → model.complete：调用一次模型接口
  → run_single_turn：返回这次调用的回复
```

在未来的 Agent 循环里，还会有助手消息、工具调用和工具结果。本课先只处理系统消息与用户消息。

`mini_agent/contracts.py` 中的 `TextModel` 只约定 `complete` 方法。Mock 和后续真实模型都可以遵守它，练习函数不需要判断具体供应商。

## 第一步：看一次离线演示

```bash
./lab doctor
./lab demo
```

演示会打印一组已准备好的消息和 Mock 返回值。它属于辅导设施；你的练习实现仍在 `exercises/lesson01.py`。

## 第二步：补全 build_messages

打开：

```text
exercises/lesson01.py
```

函数输入为 `user_input: str`，输出是消息列表。契约如下：

1. 去掉输入两端的空白字符。
2. 如果去掉空白后为空，抛出 `ValueError`。
3. 返回两条消息，第一条为 `system`，内容使用文件中的 `SYSTEM_PROMPT`。
4. 第二条为 `user`，内容是清理后的用户输入。
5. 每次调用都创建新的列表，不能把不同请求混在同一个全局列表里。

**提示：** 先考虑字符串的 `strip()`，再考虑空值判断，最后组织列表和字典。你可以先在终端用小例子验证，再写进函数。

## 第三步：补全 run_single_turn

这个函数负责把两端接起来：

1. 使用你写的 `build_messages` 取得消息。
2. 调用传入模型对象的 `complete(messages)`，恰好一次。
3. 把模型返回的文本原样返回。
4. 模型调用抛出异常时，不伪造一个“调用成功”的回复。本课先让异常向上传递。

**提示：** 这个函数只需要组织数据流，不需要写工具循环、重试、网络请求或供应商判断。

## 第四步：运行验收

```bash
./lab check 01
```

当前文件中的两个函数有意抛出 `NotImplementedError`。开始时验收失败是预期状态；填写后应该全部通过。

验收检查的行为包括：

- 空输入不能发给模型。
- 角色、顺序与内容正确。
- 不同请求的消息互不污染。
- 一次调用只调用一次模型。
- 模型返回的文本不被替换或截断。
- 模型失败会传递出来，而不是被误报为成功。

验收通过后运行你的实现：

```bash
./lab lesson01 --input '请解释一下 Agent 的作用'
```

此命令仍使用离线 Mock，会明确显示模拟标记。
